# Техническое задание: Pasynkov Tint

> Расширение GNOME Shell для наложения цветовых фильтров на весь интерфейс рабочего стола.

**Версия ТЗ:** 1.0  
**Версия первого релиза:** 0.1.0 MVP  
**Рабочее название:** Pasynkov Tint  
**Тип проекта:** GNOME Shell Extension  
**Основная система:** Ubuntu 24.04 LTS, GNOME Shell 46, Wayland  
**Рекомендуемый UUID:** `pasynkov-tint@fedor-pasynkov.ru`

---

## 1. Идея проекта

Pasynkov Tint — современный аналог расширения Tint All для GNOME Shell.

Пользователь может быстро изменить цветовое восприятие всего интерфейса: сделать изображение янтарным, зелёным, голубым, похожим на старую фотографию или полностью чёрно-белым. Интенсивность эффекта регулируется колёсиком мыши и ползунком.

Основной упор:

- быстрое управление с верхней панели;
- минимальное количество действий;
- работа со всем интерфейсом GNOME;
- сохранение выбранного фильтра;
- отсутствие заметной нагрузки на систему;
- корректная работа на GNOME 46 и Wayland.

---

## 2. Цель MVP

Создать устанавливаемое расширение GNOME Shell, которое:

1. Добавляет значок Pasynkov Tint в правую часть верхней панели.
2. Позволяет включать и выключать цветовой эффект.
3. Переключает готовые фильтры.
4. Позволяет менять силу эффекта.
5. Запоминает состояние и настройки.
6. Корректно удаляет все эффекты при отключении расширения.
7. Не блокирует мышь, клавиатуру, окна и элементы GNOME Shell.

---

## 3. Целевая платформа

### Обязательная поддержка

- Ubuntu 24.04 LTS;
- GNOME Shell 46;
- Wayland;
- один монитор;
- стандартная тема GNOME и тема Ubuntu Yaru;
- интерфейс на русском и английском языках.

### Желательная поддержка

- X11-сессия GNOME 46;
- два и более монитора;
- дробное масштабирование;
- разрешения Full HD, 2K и 4K.

### Пока не требуется

- GNOME 45 и ниже;
- GNOME 47 и выше;
- KDE Plasma, Windows и macOS;
- мобильные устройства.

Поддержку следующих версий GNOME добавлять отдельными изменениями после проверки API.

---

## 4. Термины

- **Расширение включено** — GNOME загрузил Pasynkov Tint.
- **Эффект активен** — один из фильтров применяется к интерфейсу.
- **Пресет** — готовый тип цветового эффекта.
- **Интенсивность** — сила применения выбранного эффекта от 0 до 100%.
- **Индикатор** — значок Pasynkov Tint на верхней панели GNOME.

Важно: включённое расширение не обязано означать включённый фильтр. Пользователь может оставить Pasynkov Tint загруженной, но временно отключить эффект.

## 5. Пользовательские сценарии

### Сценарий 1. Быстрое переключение

1. Пользователь нажимает на значок Pasynkov Tint.
2. Включается следующий пресет.
3. Повторные нажатия переключают пресеты по кругу.
4. После последнего пресета эффект отключается.

Порядок по умолчанию:

`Выключено → Янтарный → Зелёный → Голубой → Сепия → Чёрно-белый → Выключено`

### Сценарий 2. Изменение интенсивности

1. Пользователь наводит курсор на значок Pasynkov Tint.
2. Прокручивает колёсико вверх или вниз.
3. Интенсивность меняется с шагом 5%.
4. На экране кратко появляется уведомление, например: `Pasynkov Tint: 65%`.

### Сценарий 3. Выбор через меню

1. Пользователь открывает меню Pasynkov Tint.
2. Выбирает конкретный пресет.
3. Регулирует интенсивность ползунком.
4. Изменения применяются сразу, без кнопки «Сохранить».

### Сценарий 4. Перезапуск системы

1. Пользователь выбирает фильтр и интенсивность.
2. Выходит из системы или перезагружает компьютер.
3. После входа Pasynkov Tint восстанавливает сохранённое состояние, если это разрешено в настройках.

### Сценарий 5. Отключение расширения

1. Пользователь отключает Pasynkov Tint через Extension Manager.
2. Любой цветовой эффект сразу удаляется.
3. Значок исчезает с панели.
4. Интерфейс возвращается к нормальному виду.

## 6. Функциональные требования MVP

## 6.1. Индикатор верхней панели

Расширение должно добавить индикатор в правую часть верхней панели GNOME.

Требования:

- использовать символическую SVG-иконку;
- рекомендуемое имя файла: `pasynkov-tint-symbolic.svg`;
- размер должен соответствовать системным значкам панели;
- значок не должен ломать высоту панели;
- при активном эффекте значок должен визуально отличаться от выключенного состояния;
- индикатор должен полностью уничтожаться в `disable()`.

Варианты отображения состояния:

- выключено — обычный монохромный значок;
- включено — дополнительная маленькая точка или изменение внутренней формы значка;
- не использовать яркую полноцветную иконку, которая конфликтует со стилем GNOME.

---

## 6.2. Управление мышью

### Основное нажатие

По умолчанию основное нажатие переключает пресеты по кругу.

### Колёсико мыши

- прокрутка вверх увеличивает интенсивность на 5%;
- прокрутка вниз уменьшает интенсивность на 5%;
- минимальное значение — 5%;
- максимальное значение — 100%;
- при выключенном эффекте прокрутка изменяет сохранённую интенсивность, но не обязана автоматически включать фильтр.

### Открытие меню

Меню должно быть доступно отдельным действием.

Рекомендуемый вариант для MVP:

- основное нажатие — следующий пресет;
- правое нажатие — открыть меню.

Если правое нажатие конфликтует с API `PanelMenu.Button`, допустимо использовать более стандартную схему:

- основное нажатие — открыть меню;
- среднее нажатие — следующий пресет;
- колёсико — интенсивность.

Фактическое поведение необходимо описать в README.

## 6.3. Меню Pasynkov Tint

Меню должно содержать:

1. Переключатель `Эффект включён`.
2. Название текущего пресета.
3. Список пресетов.
4. Ползунок интенсивности.
5. Кнопку `Настройки`.

Пресеты должны быть представлены как взаимоисключающий список: одновременно выбран только один пресет.

Изменения применяются сразу.

Пример структуры:

```text
Pasynkov Tint

[●] Эффект включён

Пресет
  ○ Янтарный
  ○ Зелёный
  ○ Голубой
  ○ Сепия
  ● Чёрно-белый

Интенсивность       65%
[────────●────────────]

Настройки
```

## 6.4. Пресеты

MVP должен содержать шесть состояний.

### 1. Выключено

- изображение не изменяется;
- эффекты не должны оставаться прикреплёнными к сцене без необходимости.

### 2. Янтарный

Визуальный результат:

- тёплый оранжево-жёлтый оттенок;
- синий канал заметно ослаблен;
- текст остаётся читаемым;
- эффект не должен превращать белый фон в полностью оранжевый при средней интенсивности.

### 3. Зелёный

Визуальный результат:

- зелёный оттенок в стиле старого монохромного монитора;
- красный и синий каналы ослаблены;
- при 100% эффект может быть выраженным, но интерфейс должен оставаться различимым.

### 4. Голубой

Визуальный результат:

- холодный голубой или циановый оттенок;
- красный канал ослаблен;
- фильтр не должен просто повышать яркость экрана.

### 5. Сепия

Визуальный результат:

- изображение похоже на старую фотографию;
- цвета частично смешиваются и переводятся в коричнево-золотистую палитру;
- это не просто полупрозрачный коричневый слой.

### 6. Чёрно-белый

Визуальный результат:

- насыщенность постепенно уменьшается;
- при 100% изображение полностью лишается цвета;
- яркость и контраст не должны резко изменяться.

### Интенсивность

Для всех пресетов:

- 0% визуально соответствует отсутствию эффекта;
- 100% соответствует максимально выраженному эффекту;
- изменение должно происходить плавно;
- значение хранится как число с плавающей точкой от `0.0` до `1.0`.

## 6.5. Сохранение настроек

Для хранения использовать GSettings.

Рекомендуемые ключи:

| Ключ | Тип | Значение по умолчанию | Назначение |
|---|---:|---:|---|
| `effect-enabled` | `b` | `false` | Активен ли визуальный эффект |
| `preset` | `s` | `'amber'` | Текущий пресет |
| `intensity` | `d` | `0.65` | Интенсивность от 0.0 до 1.0 |
| `restore-state` | `b` | `true` | Восстанавливать ли эффект после входа |
| `click-action` | `s` | `'cycle'` | Действие основного нажатия |
| `show-osd` | `b` | `true` | Показывать уведомление об интенсивности |

ID схемы:

```text
org.gnome.shell.extensions.pasynkov-tint
```

Путь схемы:

```text
/org/gnome/shell/extensions/pasynkov-tint/
```

Настройки должны применяться в реальном времени через сигналы `changed::key-name`.

---

## 6.6. Восстановление состояния

При загрузке расширения:

1. Прочитать GSettings.
2. Создать индикатор.
3. Подготовить менеджер эффектов.
4. Если `restore-state = true` и `effect-enabled = true`, применить сохранённый пресет.
5. Если восстановление выключено, оставить эффект неактивным, но не удалять сохранённый пресет и интенсивность.

---

## 6.7. Уведомление об интенсивности

При прокрутке колёсика желательно показывать краткое системное OSD или уведомление:

```text
Pasynkov Tint · Янтарный · 65%
```

Требования:

- не создавать новое постоянное уведомление на каждый шаг;
- по возможности обновлять уже показанное OSD;
- не воспроизводить звук;
- возможность отключить отображение через GSettings;
- отсутствие OSD не должно блокировать выпуск MVP, если реализация нестабильна.

---

## 6.8. Несколько мониторов

Минимально допустимый результат:

- эффект применяется ко всему содержимому GNOME Shell, видимому на всех мониторах;
- после подключения или отключения монитора эффект не пропадает;
- расширение не падает при изменении конфигурации экранов.

Если используются отдельные акторы или эффекты для каждого монитора:

- пересоздавать их после сигнала изменения мониторов;
- не использовать фиксированный размер вроде «ширина основного монитора × 100»;
- каждый актор должен точно соответствовать геометрии своего монитора;
- акторы должны иметь `reactive: false` и не перехватывать события мыши.

## 7. Настройки расширения

Окно настроек создаётся в `prefs.js` с использованием GTK4 и Libadwaita.

### Страница «Основное»

- переключатель `Восстанавливать эффект после входа`;
- выбор поведения основного нажатия:
  - переключать пресет;
  - включать или выключать эффект;
  - открывать меню;
- переключатель `Показывать интенсивность на экране`.

### Страница «Пресеты» — необязательна для MVP

В первой версии можно только показывать список встроенных пресетов без редактирования.

Редактирование цветов и создание пользовательских пресетов перенести в версию 0.2.

### Страница «О расширении»

- название Pasynkov Tint;
- версия;
- краткое описание;
- ссылка на репозиторий;
- лицензия;
- автор;
- упоминание Tint All как источника идеи, если использовались его код или конкретная реализация.

## 8.2. Рекомендуемая структура проекта

```text
pasynkov-tint@fedor-pasynkov.ru/
├── extension.js
├── metadata.json
├── prefs.js
├── stylesheet.css
├── README.md
├── LICENSE
├── icons/
│   └── pasynkov-tint-symbolic.svg
├── lib/
│   ├── effectManager.js
│   ├── indicator.js
│   └── presets.js
└── schemas/
    └── org.gnome.shell.extensions.pasynkov-tint.gschema.xml
```

### Назначение файлов

- `extension.js` — жизненный цикл расширения, создание основных компонентов.
- `effectManager.js` — применение, обновление и удаление эффектов.
- `indicator.js` — индикатор, меню и обработка мыши.
- `presets.js` — описание пресетов и порядок переключения.
- `prefs.js` — окно настроек.
- `metadata.json` — UUID, версия, описание и поддерживаемые версии Shell.
- `stylesheet.css` — только стили интерфейса расширения.
- `gschema.xml` — схема настроек.

Для самого первого прототипа допустимо хранить код в `extension.js`, но перед релизом 0.1.0 логику эффектов и индикатора следует разделить.

  "url": "https://github.com/USERNAME/pasynkov-tint"

До создания репозитория заменить `USERNAME` или временно удалить поле `url`.

## 8.4. Менеджер эффектов

Создать класс `EffectManager` с публичными методами:

```text
enableEffect(presetId, intensity)
disableEffect()
setPreset(presetId)
setIntensity(intensity)
refresh()
destroy()
```

Требования:

- единственный источник истины для активного эффекта;
- повторное применение того же пресета не создаёт дубликаты;
- изменение интенсивности обновляет существующий эффект;
- `destroy()` удаляет все эффекты, акторы и сигналы;
- вызов `disableEffect()` несколько раз не вызывает ошибку;
- неизвестный `presetId` заменяется безопасным значением по умолчанию.

## 8.5. Способ реализации визуальных эффектов

### Предпочтительный путь для первой рабочей версии

Использовать встроенные графические эффекты GNOME/Clutter, применяемые к подходящей группе сцены GNOME Shell.

Для поведения, похожего на оригинальный Tint All, можно прототипировать комбинацию:

- эффекта уменьшения насыщенности;
- эффекта яркости и контраста;
- разных значений каналов для каждого пресета.

Преимущества:

- меньше кода;
- высокая производительность;
- нет полноэкранного актора, который может случайно перекрыть интерфейс;
- проще реализовать чёрно-белый режим.

### Альтернативный путь

Использовать пользовательский GLSL-эффект или цветовую матрицу.

Он необходим, если встроенные эффекты не позволяют получить качественную сепию или одинаково работают не на всех элементах интерфейса.

### Полупрозрачный overlay

Допустимо использовать только для простых цветных оттенков, но он не должен быть единственным способом реализации сепии и чёрно-белого режима.

Если используется overlay:

- `reactive: false`;
- не перехватывать фокус;
- не перекрывать системные диалоги недоступным слоем;
- создавать точные акторы по геометрии мониторов;
- удалять акторы при выключении эффекта;
- обновлять геометрию при изменении мониторов.

### Порядок разработки

1. Сделать прототип встроенных эффектов.
2. Проверить все пресеты на GNOME 46 Wayland.
3. Если качество сепии неудовлетворительно, заменить только её реализацию шейдером.
4. Не начинать MVP сразу с большого универсального шейдерного движка.

## 8.6. Управление ресурсами

Расширение не должно:

- создавать постоянный цикл обновления кадров;
- использовать `setInterval` для эффекта;
- пересоздавать эффект при каждом движении мыши;
- хранить уничтоженные акторы;
- оставлять подключённые сигналы после `disable()`;
- записывать GSettings десятки раз в секунду без необходимости.

Изменение эффекта происходит только при:

- выборе пресета;
- изменении интенсивности;
- включении или выключении эффекта;
- изменении конфигурации мониторов;
- загрузке сохранённых настроек.

---

## 8.7. Жизненный цикл

### `enable()`

Должен:

1. Получить GSettings.
2. Создать `EffectManager`.
3. Создать индикатор.
4. Подключить необходимые сигналы.
5. Восстановить состояние.

### `disable()`

Должен:

1. Отключить и удалить эффект.
2. Удалить все overlay-акторы, если они есть.
3. Отключить все сигналы.
4. Уничтожить индикатор и меню.
5. Освободить ссылки на объекты.
6. Не менять сохранённые пользовательские настройки без причины.

После `disable()` интерфейс обязан выглядеть так, будто Pasynkov Tint не была запущена.

---

## 8.8. Обработка ошибок

- Ошибки писать через `console.error()` с префиксом `[Pasynkov Tint]`.
- Информационные сообщения для разработки — через `console.debug()`.
- Не показывать пользователю технический стек ошибок.
- При ошибке применения пресета удалить повреждённый эффект и вернуть нормальные цвета.
- Если схема настроек недоступна, расширение должно завершить включение безопасно или вывести понятную ошибку в журнал.

Пример:

```text
[Pasynkov Tint] Failed to apply preset "sepia": <error message>
```

## 9. Нефункциональные требования

### Производительность

- отсутствие постоянной заметной загрузки CPU;
- отсутствие утечки памяти при многократном переключении;
- отсутствие заметных рывков анимаций GNOME;
- переключение пресета визуально происходит быстрее чем за 200 мс;
- прокрутка интенсивности ощущается мгновенной.

### Надёжность

- 100 последовательных переключений не создают дубликаты эффектов;
- отключение расширения всегда возвращает исходные цвета;
- повторное включение расширения работает без выхода из системы;
- ошибка одного пресета не должна ломать весь GNOME Shell.

### Безопасность и приватность

- никаких интернет-запросов;
- никакой телеметрии;
- никакого сбора данных;
- никаких команд через shell без необходимости;
- никаких фоновых процессов;
- никакого чтения пользовательских файлов.

### Доступность

- элементы настроек имеют понятные подписи;
- не полагаться только на цвет для обозначения включённого состояния;
- поддерживать навигацию с клавиатуры в окне настроек;
- названия пресетов должны быть переводимыми.

## 17. Возможные риски

### Риск 1. Эффект применяется не ко всему экрану

Причина: разные группы сцены GNOME Shell или изменение внутреннего API.

Решение:

- протестировать `Main.uiGroup` и другие подходящие группы;
- не прикреплять один и тот же эффект одновременно к нескольким родителям;
- при необходимости перейти на отдельные эффекты или акторы для мониторов.

### Риск 2. Overlay закрывает интерфейс

Причина: неправильный `reactive`, z-порядок или размер актора.

Решение:

- использовать `reactive: false`;
- не принимать фокус;
- тестировать системные меню и Overview;
- гарантированно удалять overlay в `disable()`.

### Риск 3. Сепия выглядит как коричневая плёнка

Причина: использование только полупрозрачного цвета.

Решение:

- применять цветовую матрицу или GLSL;
- сначала уменьшать насыщенность, затем преобразовывать каналы.

### Риск 4. GNOME Shell зависает после ошибки

Причина: необработанное исключение внутри расширения.

Решение:

- маленькие независимые классы;
- безопасный `destroy()`;
- проверки на `null`;
- обработка ошибок при применении эффекта;
- тестировать включение и отключение после каждой функции.

### Риск 5. Код от старого GNOME не запускается

Причина: старые импорты вида `imports.ui.main` и отсутствие ES-модулей.

Решение:

- писать проект сразу под GNOME 46;
- использовать `import ... from 'gi://...'`;
- использовать современные импорты `resource:///org/gnome/shell/...`;
- не просить ИИ просто «обновить старое расширение», не указав целевую версию GNOME.
